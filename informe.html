Caso de estudio | Del requisito a la evidencia

SpringEduManager: un sistema académico con permisos verificables

Actividad. Desarrollo de una aplicación que relaciona estudiantes, cursos, inscripciones, prácticas y evaluaciones. El trabajo integra las lecciones del módulo de Spring en una solución ejecutable.

Desafío principal. Mantener coherencia entre datos académicos y permisos: un estudiante debe consultar sus propios registros, mientras un administrador realiza las operaciones de gestión. La API debe respetar las mismas reglas de negocio que la interfaz.

Solución propuesta. Separar controladores web y REST, reutilizar servicios de negocio y persistir las entidades mediante repositorios JPA. Aplicar autenticación, restricciones por rol, validación de entradas y protección de operaciones sobre registros relacionados.

Arquitectura de la solución

EntradaProcesamientoPersistencia
Web + Thymeleaf
API REST + JSON		Spring Security
Controlador → servicio		Repositorio JPA
Base H2 en archivo

Herramienta principal y justificación. Spring Boot permite reunir configuración, servidor y dependencias en una aplicación ejecutable. Spring MVC organiza la interacción; JPA facilita la persistencia y Spring Security centraliza los permisos. H2 en archivo simplifica la demostración local y conserva datos después de reiniciar.

Decisiones técnicas. Usar DTO para limitar los campos editables; asignar USER al registro público; conservar CSRF en formularios; separar la autenticación HTTP Basic de la API; impedir eliminaciones que afecten relaciones académicas.

Habilidades aplicadas

Programación Java, arquitectura por capas, modelado relacional, validación, autenticación y autorización, diseño REST, gestión de dependencias Maven y pruebas de integración.

Por qué elegí este proyecto. Reúne desarrollo, integración y criterios de operación próximos a mi experiencia profesional. Permite explicar el recorrido completo desde una necesidad hasta una implementación cuya conducta puede revisarse. Es evidencia formativa; no corresponde a un despliegue comercial.

Aprendizajes. Una interfaz que oculta opciones debe acompañarse de autorización en el servidor. Las reglas compartidas deben residir en servicios. Las relaciones de datos requieren validar borrados y duplicados. Las pruebas aportan evidencia más precisa que una afirmación general de funcionamiento.
